## Decided

**D2, assembly for speed: kept** (the user, 2026-10-07). D2 names eight files written in
assembly for speed beside those the ABI requires: the fast path of `__c6xabi_divd`/`divf`
(RCPDP and RCPSP, which cpp11 cannot reach), and `memcpy`, `memmove`, `memset`, `strlen`,
`strchr`, `strcmp` (cpp11 does not pipeline a loop that exits on the data). Our own code,
written from SPRUFE8 and SPRAB89B. Each keeps a plain C++ reference beside it (`X-reference.cpp`,
compiled only under `RTS6X_REFERENCE`), for reading and comparison: `make reference` or
`build.cmd reference` builds `rts6xr.lib`, `R=r tests/run.sh` tests it, and
`tools/speed-reference` prints both libraries' cycles (the user, 2026-10-07).

## Open, found this round and not assigned

- `atoi` and the integer conversions (`NumberText`) take about 7x TI's cycles; they
  hold the strtod benchmark at 2.28x where it would be about 1.4x.
- cpp11 does not pipeline loops that exit on the data or accumulate a value, rebuilds
  constants inside such loops, and keeps only about eight locals in registers. This is
  what the assembly in D2 stands in for, and what keeps sin/cos at 2.7x and sqrt at 1.86x.
- cpp11: any other C6xSched pass that reads liveness after rewriting text may have the
  same stale-liveness exposure the value-numbering pass had; not audited.
- cpp11: a reference-to-function data member is refused in a mem-initialiser; a class
  whose virtuals are all inline still gets a vtable when nothing builds one; a static
  data member is hidden by a global of the same name.
- cpp11 x86_64-windows: `throw-pointer-base-adjust` prints its lines in another order
  (on main before this round too).
- vm6747sim does not translate text-mode files as the Windows host does (CR LF); no
  program of the 780 sees it.
- `tools/referee.cmd` waits for ever when a TI simulator session fails to start; it
  needs a retry or a time-out.
- `tests/helpers/division.cpp` takes about 355M cycles at -O0, the slowest case in
  run.sh.
